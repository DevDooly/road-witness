# RoadWitness 개발 계획

작성일: 2026년 10월 6일

첫 개발 플랫폼은 사용자 결정에 따라 **Android로 확정**했습니다. 초기 개발과 실기기 검증은 Android에 집중하며, iOS는 Android 베타 검증 이후 확장 대상으로 다룹니다.

RoadWitness는 주행 중 위반 의심 장면을 기록하고, 주행 후 사용자가 확인한 영상과 정보를 신고에 사용할 수 있도록 정리합니다. 첫 목표는 **증거 준비 기능과 한 가지 유형의 실시간 후보 탐지가 연결되는 Android 제한 베타**입니다.

일정은 Android 개발자 1명이 주로 이 프로젝트에 집중하고, 테스트용 휴대폰과 사용 권한이 있는 샘플 영상을 확보한다는 가정의 10~12주 초안입니다. 학습 데이터 확보, 모델 개발, iOS 구현, 심사와 서비스 출시 기간은 별도입니다. 1~2주차 결과로 지원 기기와 일정을 조정합니다.

## 제품 목표와 사용 흐름

사용자는 출발 전에 휴대폰을 고정하고 촬영을 시작합니다. 주행 중 앱은 촬영 상태를 표시하며 후보 장면을 자동 저장합니다. 도착 후 후보 목록에서 장면을 검토하고, 번호판과 시각·위치·유형을 확인한 뒤 영상과 신고 문안을 내보냅니다.

저장된 블랙박스 영상을 가져오는 흐름도 지원합니다. 가져온 영상의 촬영 시각과 위치가 없으면 사용자가 근거를 확인해 입력하며, 가져온 시각을 촬영 시각으로 채우지 않습니다.

| 기능 | 구현 내용 | 사용자 확인 또는 제한 |
| --- | --- | --- |

| 주행 기록 | 연속 영상, 촬영 세션, 시각과 위치 표본 기록 | 권한 거부·GPS 결측도 저장 |
| 차량 탐지 | 차량 위치와 같은 차량의 시간별 이동 추적 | 가림·야간·작은 차량은 판단 보류 |
| 후보 생성 | 실험으로 선정한 한 가지 유형의 장면 변화 탐지 | 유형별 근거와 불확실성 표시 |
| 증거 편집 | 후보 전후 구간 자동 제안, 사용자 구간 조절, MP4 내보내기 | 원본과 잘라낸 사본을 연결 |
| 번호판 | 선명한 프레임에서 번호판 후보와 OCR 결과 제안 | 인식 불가·수동 수정·확인 상태 지원 |
| 정보 요약 | 확인된 일시·위치·번호판·관측 내용을 문안으로 작성 | 누락 필드는 미확인으로 표시 |
| 신고 준비 | 영상 저장·공유, 요약문 복사, 신고 채널 안내 | 사용자가 외부 채널에서 제출 |
| 자료 관리 | 사건별 보관·삭제, 저장 공간 한도 | 내보낸 파일과 앱 내부 파일을 구분 |

첫 버전에는 자동 신고 제출, 모든 위반 유형 판정, 사용자 계정·영상 서버 업로드, 구독·광고를 포함하지 않습니다. 요약문은 확인된 필드를 조합하는 템플릿으로 시작합니다. 생성형 모델은 사실 검증과 비용 필요성이 확인될 때 추가합니다.

## 첫 자동 탐지 유형 선정

차량 탐지만으로 위반 여부가 결정되지는 않습니다. 첫 2주 동안 영상에 차량·차선·장면 변화가 충분히 보이는지 확인하고, **차선 경계 침범 의심 장면**을 첫 실험 후보로 평가합니다. 실선 여부, 도로 조건, 차량 추적이 불명확한 장면은 판단을 보류합니다.

| 후보 유형 | 필요한 정보 | 개발 순서 |
| --- | --- | --- |
| 차선 경계 침범 의심 | 차량 추적, 차선 위치, 카메라 움직임 보정 | 첫 실험 후보, 자료 검토 후 선정 |
| 신호위반 의심 | 해당 차로의 신호, 정지선, 차량 통과 시점 | 후속 실험 |
| 끼어들기·급차로 변경 의심 | 차량 궤적, 차로 관계, 충분한 전후 맥락 | 후속 실험 |
| 과속 의심 | 보정된 속도 추정과 해당 구간 제한속도 | 추가 정보 확보 후 검토 |

실시간 촬영 가능성은 확인되지만 자동 후보 성능이 부족하면, 촬영·수동 장면 지정·증거 편집을 먼저 배포하고 탐지는 별도 실험으로 계속합니다. 이 경우 실시간 자동 탐지는 완료 기능으로 표시하지 않습니다.

| 1 증거 준비 흐름 | 3~4주차 | 영상 가져오기, 타임라인, 수동 사건 생성, 구간 편집, 정보 입력, 요약문·MP4 내보내기 | 합성 또는 사용 권한이 있는 영상으로 가져오기부터 내보내기까지 재현 |
| 2 주행 기록 | 5~6주차 | CameraX 촬영, 세션·위치 기록, 임시 영상 보관, 사건 전후 구간 보호, 권한·공간 부족 처리 | 종료·권한 거부·저장 공간 부족을 처리하고 원본/클립 연결을 복구 |
| 3 후보 탐지 연결 | 7~9주차 | 차량 탐지·추적, 선정 유형 후보 생성, OCR, 후보 병합, 비동기 검토 목록 | 고정 평가 자료에서 후보·번호판 지표를 측정하고 합의한 베타 기준 통과 |

실시간 후보 탐지 단계는 촬영 안정성과 평가 자료 준비에 의존합니다. 측정 없이 다음 단계로 넘어가지 않으며, 미달 항목은 기능·지원 조건·일정 중 무엇을 조정할지 기록합니다.

## 1주차 실행 작업

1. `apps/android`에 Android Studio 프로젝트를 생성하고 Kotlin·Compose 빌드를 고정합니다.
2. 동시 개발할 지원 기기 2대와 Android 버전을 기록합니다.
3. CameraX 미리보기·녹화·프레임 분석을 동시에 실행하고 분석 빈도와 해상도를 바꿔 측정합니다.
4. 저장된 영상의 임의 구간을 Media3로 내보내고 원본 시간 구간과 비교합니다.
5. 한국 번호판 표본에서 번호판 영역 검출과 한국어 OCR을 분리해 시험합니다.
6. 촬영 시작 시각·영상 시간축·위치 표본을 연결하는 작은 세션 모델을 구현합니다.
7. 녹화 공백, 발열, 배터리, 저장 공간 증가량, 분석 지연을 기록하고 자동 탐지 유형을 선정합니다.

## 베타 검증 목표

다음 수치는 구현 전에 합의할 **초기 목표**이며, 현재 성능이나 신고 접수 요건을 뜻하지 않습니다. 1~2주차 결과에 따라 조정하고 평가 자료·기기·조건을 함께 기록합니다.

| 항목 | 초기 목표 | 측정 방식 |
| --- | --- | --- |
| 촬영 안정성 | 기기 2대에서 30분 운용, 충돌 0건, 영상 공백 모두 탐지·표시 | 파일 시간축과 세션 로그 대조 |
| 후보 지연 | 선택한 분석 빈도에서 후보 생성 지연 p95 2초 이내 | 영상 관측 시점부터 후보 저장 시점까지 |
| 후보 정확도 | 지원 조건의 고정 자료에서 precision 80% 이상 | 사건 단위 TP/FP/FN, recall과 시간당 오탐도 함께 기록 |
| 번호판 | 사람이 읽을 수 있는 지원 표본에서 전체 문자열 일치율 90% 이상 | 정답 비교, 판독 불가율과 잘못된 제안 비율 병기 |
| 구간 보존 | 합성 사건의 지정 전후 구간 누락 0건 | 경계 시점·세그먼트 접합·최종 파일 재생 확인 |
| 요약문 | 확인하지 않은 번호판·시각·위치를 사실로 채운 사례 0건 | 결측·수정·출처가 다른 입력으로 검토 |
| 오프라인 흐름 | 네트워크 없이 녹화·편집·요약·파일 저장 가능 | 모델 준비 상태 포함 비행기 모드 확인 |

서로 겹치는 프레임을 학습과 평가에 나누지 않습니다. 주행 세션별로 자료를 분리하고, 정상 주행과 야간·가림·빗길·굴곡 도로도 포함합니다. 유형별 표본 수가 적으면 결과를 탐색적 수치로 표시합니다.

## 증거와 신고 정보

원본은 편집하지 않고, 잘라낸 사본의 원본 ID·시작/끝 시간·해시를 연결합니다. 신고용 영상에는 상황을 가리는 자막·추적 박스를 기본으로 넣지 않습니다. 분석 표시가 있는 미리보기와 제출용 사본을 구분합니다. 해시는 파일 동일성 확인 수단이며 촬영 내용의 진실성을 보증하지 않습니다.

촬영 일시·위치·번호판은 값과 함께 출처, 정확도 또는 확인 상태를 보관합니다. 영상에 근거가 없거나 GPS가 없으면 미확인 상태를 유지합니다. 수정 전 자동 제안과 사용자가 확인한 최종값을 구분합니다.

국내 신고 흐름을 첫 대상으로 제안합니다. 외부 신고 채널의 영상 규격, 필수 정보, 기한, 공유 지원과 공식 연동 가능성은 베타 전에 최신 안내로 확인합니다. 접수 완료 상태는 실제 접수 결과나 사용자의 명시적인 확인이 있을 때만 기록합니다.

## 이후 확장

Android 제한 베타를 통과하면 신호·차선·도로 맥락을 이용한 유형별 탐지를 확장합니다. 그다음 iOS 촬영·추론 실험, 선택형 서버 재분석, 공식 신고 연동 순으로 검토합니다. 각 확장은 데이터 근거, 사용자 동의, 비용과 성능 검증을 갖춘 뒤 별도 단계로 진행합니다.
